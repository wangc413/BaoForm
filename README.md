# BaoForm README

BaoForm（原「主表数值生成器」）是一个纯静态的配方折算 / 生产表单工具，目前支持两个渠道：

- **盒马**：肉包、烧麦、菜包
- **快乐猴**：肉包、菜包、水饺、糯米鸡、菜团子

页面入口是 `calculator.html`，无构建、无依赖；双击打开，或用本地静态服务器访问。

## 2. 数据模型

所有产品都挂在全局 `PRODUCTS` 下：

```js
PRODUCTS[channel][product] = {
  label: '肉包',
  materials:   [{ name, category, perBox }],              // 原料用料计算表
  requisition: [{ maker, spec, unit, perBox, ...取整规则 }], // 领料单
  filling:     [{ name, category, perBox }],              // 制馅单
  fillingTotalExclude: ['...'],                           // 可选：制馅单合计要排除的行名
  mixfill:     [{ name, maker, perBox, standard }],       // 拌馅记录表
  dough:       [{ name, maker, perBox, standard }],       // 和面记录表
}
```

- `perBox` 统一表示**单箱使用重量（kg）**。
- 数组为空时，对应页签自动隐藏。
- `standard` 表示**每锅标准用量（kg）**，只用于拌馅/和面。

## 3. 通用算法

### 3.1 原料用料计算表

页面只做两件事：

```
某原料总使用重量 = perBox × 入库箱数
合计 = 所有原料总使用重量之和
```

`perBox` 的来源分两种：

- **盒马**：已经按盒马配方折算好，直接维护在 `hema.js`；
- **快乐猴**：从批次配方现场折算，公式见 3.2。

### 3.2 从批次配方折算 perBox（快乐猴用）

设：

- `W`：箱规（kg/箱）
- `w`：单重（kg/个）
- `f`：馅重（kg/个）
- `d`：皮重（kg/个）
- `B馅`、`B皮`：馅、皮一批的合计（kg）

```
每箱个数 N = W ÷ w
每箱馅   F = N × f = W × (f ÷ w)
每箱皮   D = N × d = W − F

馅系数 k馅 = F ÷ B馅
皮系数 k皮 = D ÷ B皮

某原料单箱用量 = 该原料批次用量 × k馅（或 k皮）
```

校验：所有原料单箱用量相加，应等于 `W`。

### 3.3 领料单取整规则（盒马）

`app.js` 顶部注释里的规则，优先级从高到低：

| 字段 | 规则 |
|---|---|
| `flour: true` | 小麦粉总量 ÷ flour 行数 ÷ 25，向上取整到袋，再 ×25 |
| `roundUpTo: N` | `⌈用量 ÷ N⌉ × N` |
| `plusOne: true` | `⌈用量⌉ + 1` |
| `roundPlus: N` | 四舍五入取整 + N |
| 都没有 | `perBox × 箱数`，保留两位小数 |

优先级：`flour > roundUpTo > plusOne > roundPlus > 默认`。

### 3.4 锅次表

#### 拌馅记录表（逐行模式）

```
总用量 = perBox × 箱数
锅数   = ⌈总用量 ÷ standard⌉
满锅数 = ⌊总用量 ÷ standard⌋
余量   = 总用量 − 满锅数 × standard
```

表格渲染时：

- 满锅显示 `✓`；
- 余量显示数字；
- 锅数取所有行最大值 `maxPots`；
- `maxPots > 4` 时，中间锅次合并成一列（依赖“各行锅数最多相差 1”的现有配比假设）；
- `standard = 0` 时按 1 锅处理。

#### 和面记录表（公共锅次模式）

和面不是每种物料各算各的锅，而是所有物料共用一个计划：

```
ratio_i = 总用量_i ÷ standard_i
整锅数 n = ⌊min(ratio_i)⌋
余量比例 frac = min(ratio_i) − n
```

规则：

- `frac > 0.5`：整锅数不变，把每种物料的剩余量 `总用量 − n × standard` 放到最后一锅（第 `n+1` 锅“余量”），不再拆前一锅；
- `frac ≤ 0.5`：退掉一个整锅，把这一锅和剩余量合起来平分到第 `n`、`n+1` 锅（两锅“均分”）；
- `frac = 0`：只做 `n` 个整锅，不做尾锅。

表格：

- 整锅显示 `✓`；
- 标准用量列最多 2 位小数（0.86、0.52 这类原样显示），其余数量显示 2 位小数；
- `frac > 0.5` 显示一列 `第n+1锅（余量）`，数值为每种物料的剩余量；
- `frac ≤ 0.5` 显示两列 `第n锅（均分）`、`第n+1锅（均分）`，两列数值相同；
- 不设余量列；尾锅会把剩余物料全部用完。

例：盒马肉包 1080 箱，见 4.5。

### 4.2 原料表

盒马的 `perBox` 是**已经折算好的单箱用量**，直接维护在 `hema.js` 的 `*_MATERIALS` 数组里，页面不再从批次配方推导。

例：肉包小麦粉 `perBox = 2.77808`，100 箱：

```
总使用重量 = 2.77808 × 100 = 277.81kg
```

### 4.3 领料单

以肉包 100 箱为例：

- **面粉**：小麦粉总量 277.808kg，2 个 flour 行：

```
277.808 ÷ 2 ÷ 25 = 5.556 → 向上取整 6 袋
每行 6 × 25 = 150kg
```

- **酵母**（`roundUpTo: 10`）：`0.02072×100=2.072 → ⌈2.072÷10⌉×10 = 10kg`
- **盐**（`roundPlus: 5`）：`0.02168×100=2.168 → round(2.168)+5 = 7kg`
- **膨松剂**（`plusOne`）：`⌈1.552⌉+1 = 3kg`

### 4.4 制馅单

肉包有独立制馅单，22 行，`perBox` 直接维护。

菜包制馅单 21 行，按「菜包-用量计算-制馅单」的单箱使用重量（出品率前）维护，合计 8.084216kg；×0.95 出品率 = 7.68kg 箱规。猪油的总行未列入，只放「猪油-馅料」「猪油-皮料」，避免和拆分项重复。

烧麦制馅单 29 行，按「蛋黄烧麦-用量计算-制馅单」的单箱使用重量（出品率前）维护，合计 9.513939kg；×0.908141 = 8.64kg 箱规。烧麦的白砂糖是馅料、没有拆分行，所以不能排除；产品单独配置 `fillingTotalExclude`。

合计规则：优先用产品数据里的 `fillingTotalExclude`，没有配置时默认排除 4 项：

```
默认排除：饮用水、饮用水干料吸收水分、白砂糖、食用盐
```

- 肉包/菜包：用默认 4 项；
- 烧麦：只排除 `饮用水`、`饮用水-馅料里的干料吸收的水`、`食用盐`。

注意：排除的是“汇总行”，对应的 `-馅料`/`-皮料` 拆分行已经单列，排除它们是为了避免重复计算；所以合计仍包含拆分出来的水和糖，不是纯干料。规则按**中文名称**匹配，后续改配方名称时需要同步改数据里的 `fillingTotalExclude`。

### 4.5 拌馅记录表 / 和面记录表

- 拌馅：11 行，逐行模式；`standard` 为每锅标准（葱 10、水 100、糖 22.5……）；
- 和面：8 行，公共锅次模式；`standard` 为每锅标准（八星包子粉 53.6、包子粉 53.6、水 40.9、猪油 1.0、糖 7.0、酵母 0.8、膨松剂 0.6、盐 0.1）；
- 标准用量最多 2 位小数（0.86、0.52 这类原样显示），其余用量显示 2 位小数；
- 面粉/水/猪油的标准按现有糖 7kg/锅 反推；面粉按八星包子粉、包子粉各 50% 拆分。

### 5.3 肉包

**数据来源**：`js/data/kuailehou.js` 的 `KH_ROUBAO_MATERIALS`。

- 馅：配方表 13 行，实际合计 **100.05kg**（表内写 100，是 `SUM` 少算了最后 0.05kg）；
- 面皮：按左边配方表 **75.75kg**；
- 产品参数：8kg/箱、100 个、馅 28g、皮 52g。

```
F = 8 × 28/80 = 2.8kg
D = 8 − 2.8 = 5.2kg
k馅 = 2.8 ÷ 100.05 = 0.027986
k皮 = 5.2 ÷ 75.75 = 0.068647
```

例：`2#肉 36×0.027986=1.0075`；`八星粉 50×0.068647=3.4323`；`老面 5×0.068647=0.3432`。

合并项：

```
水 = 11×0.027986 + 19×0.068647 = 1.6121
糖 = 0.3×0.027986 + 0.5×0.068647 = 0.0427
盐 = 0.9×0.027986 + 0.05×0.068647 = 0.0286
```

合计：18 行，**8.0000kg**。

### 5.8 出品率与半成品

**出品率 = 产出 ÷ 投入**，只在采购/成本时使用：

```
采购量 = 配方用量 ÷ 出品率
```

- 100%：1:1；
- 90%：要买得比用的多（小香葱、姜）；
- 430%：干香菇泡发（8kg 泡发香菇 ← 1.86kg 干香菇）；
- 150%：生糯米蒸熟（100kg 蒸制糯米 ← 66.7kg 生糯米）。

**原料表不乘也不除出品率**，因为配方里的用量已经是可用量。

半成品单列（不强行展开成生料）：老面、蒸制糯米、腌鸡胸肉、泡发香菇、大葱油、馅料宝、熟玉米糁、小麦淀粉芡。

## 6. 新增产品 / 渠道

### 6.1 新增快乐猴产品

1. 在 `kuailehou.js` 定义 `*_MATERIALS` 等数组；
2. 在 `PRODUCTS.kuailehou` 增加 key：

```js
newkey: { label: '新产品', materials: ..., requisition: ..., filling: ... }
```

## 10. PWA 与 GitHub Pages 部署

### 10.1 相关文件

- `site.webmanifest`：应用名称、图标、`start_url`、`scope`、`display: standalone`
- `sw.js`：Service Worker，缓存应用壳和本地数据，断网时回退到缓存的 `calculator.html`
- `.github/workflows/deploy-pages.yml`：推送到 `main` 自动部署 GitHub Pages
- `.nojekyll`：关闭 GitHub Pages 的 Jekyll 处理
- `icon-192.png` / `icon-512.png`：PWA 安装图标
- 工作流会在 `_site` 里同时生成 `index.html`（站点根路径）和 `calculator.html`（manifest 的 `start_url`）

### 10.2 首次部署

1. 在 GitHub 新建一个 **public** 仓库，例如 `BaoForm`。
2. 仓库 **Settings → Pages → Build and deployment → Source** 选 **GitHub Actions**。
3. 本地安装 Git for Windows 或 GitHub Desktop，然后执行：

```bash
cd D:\wangcheng\program\calculator
git init
git add .
git commit -m "BaoForm PWA"
git branch -M main
git remote add origin https://github.com/<你的用户名>/BaoForm.git
git push -u origin main
```

当前机器没有 `git` / `gh`，所以这一步需要在你的 Git 环境执行；或者把仓库地址给我，我再按你的远端配置处理。

不想装 Git 也可以走 GitHub 网页：新建仓库后，用 **Add file → Upload files** 上传根目录文件；再 **Add file → Create new file**，文件名填 `.github/workflows/deploy-pages.yml`，把本仓库同名文件的内容粘进去，提交即可。

4. 推送后会自动运行 `Deploy BaoForm to GitHub Pages`，完成后地址是：

```
https://<你的用户名>.github.io/BaoForm/
```

5. 首次打开页面后 Service Worker 会缓存应用；之后断网刷新仍可使用。

### 10.3 手机添加到主屏幕

- **Android Chrome**：打开网址 → 右上角菜单 → “安装应用 / 添加到主屏幕”
- **iPhone Safari**：打开网址 → 分享 → “添加到主屏幕”

GitHub Pages 默认提供 HTTPS，满足 PWA 要求；本地 `localhost` 也可以测试 Service Worker。

### 10.4 更新与缓存

- 修改后 `git push` 到 `main`，Actions 自动重新部署；
- 工作流会把 `sw.js` 里的 `baoform-v1` 替换成当前 commit SHA，旧缓存会在 activate 时清理；
- 如果是手动部署（不用 Actions），把 `sw.js` 的 `baoform-v1` 改成新的版本号再上传。

### 10.5 离线验证

1. 用 Chrome 打开线上地址，DevTools → Application → Service Workers，确认状态为 activated；
2. Network 面板勾选 **Offline**，刷新页面，应仍能打开并计算；
3. 第一次必须联网打开一次，等缓存完成后再断网测试。

本机已用 Edge + DevTools Protocol 实测通过：

- Service Worker 状态：`activated`；
- 缓存文件数：15；
- 离线刷新后标题仍为 `BaoForm · 生产表单`；
- `Page.getInstallabilityErrors` 返回空数组，可安装。
